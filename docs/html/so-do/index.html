Sơ đồ tương tác — Flash-Core

Năm trang tự chứa (một file HTML, mở thẳng bằng trình duyệt, không cần server). Mỗi trang đều có: tìm kiếm, bấm vào một khối để tô đường đi liên quan, vài "chương" xem nhanh, đổi sáng/tối và xuất ảnh PNG/SVG.

Chỉ mở một trang? Mở Bản đồ tổng — nó trả lời cả bốn câu (nghiệp vụ, thành phần, công nghệ, kiến thức) ở mức tóm tắt, rồi tuỳ chỗ nào cần sâu thì nhảy sang trang tương ứng.

★ Bản đồ tổng

Toàn cảnh trên một màn hình: người mua → API → Postgres, worker chạy nền, và bốn thẻ tóm tắt nghiệp vụ / thành phần / công nghệ / kiến thức.

Mở sơ đồ

1 · Luồng nghiệp vụ

Từ lúc bấm "Săn ngay" tới PAID: trừ kho ngay, giữ chỗ 15 phút, nhánh 409 hết hàng và nhánh tự huỷ trả hàng về kho.

Mở sơ đồ

2 · Thành phần hệ thống

Hai tiến trình (API, worker) trên cùng một codebase, các module nghiệp vụ, ba kho dữ liệu và ba quy tắc giữ ranh giới.

Mở sơ đồ

3 · Công nghệ theo một request

Một POST /orders đi qua Guard → Zod → order → Postgres/Redis → BullMQ → worker, kèm lý do chọn từng công nghệ.

Mở sơ đồ

4 · Kiến thức tổng kết

Lộ trình các phase, bốn bài học cốt lõi, hai bug thật mà không test nào đỏ, và những con số đo được.

Mở sơ đồ

Mở cái nào khi nào

  • Giới thiệu dự án cho người lạ trong 2 phút → Bản đồ tổng, rồi Luồng nghiệp vụ.
  • Người mới vào code → Thành phần hệ thống, sau đó bản đồ code để biết file nào ở đâu.
  • Phỏng vấn hỏi "vì sao chọn cái này" → Công nghệ theo một request, chi tiết ở demo-phong-van.
  • Ôn lại đã học được gì → Kiến thức tổng kết, đáp án đầy đủ ở sổ tay kỹ thuật.

Sửa sơ đồ thế nào

Mỗi trang .html có một file .json nguồn nằm cạnh nó (ví dụ 01-nghiep-vu.workflow.json). Sửa JSON rồi sinh lại bằng skill Archify — đừng sửa tay file HTML, nó là bản dựng ra.

Nội dung trong sơ đồ không phải nguồn sự thật: mọi câu "vì sao" thuộc tech-playbook, mọi con số thuộc specs, trạng thái dự án thuộc CLAUDE.md. Sơ đồ chỉ trình bày lại. Giao diện điều khiển của trang sơ đồ là tiếng Anh (Archify chỉ hỗ trợ en/zh-CN), nội dung thì tiếng Việt.
